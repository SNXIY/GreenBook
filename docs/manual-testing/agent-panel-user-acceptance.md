# Agent 面板手工验收测试用例（用户视角）

> 这份清单是给你**自己在浏览器里照着操作**用的：每一行操作都是真实用户会做的输入，
> 每一行预期都是用户界面上应该看到的**用户语言**（不是执行 ID、GoalTree、Step、
> ToolCall 这些技术字段）。
>
> 验收准则（0813 设计目标）：
> 1. 发请求后**尽快看到真实业务动作**，绝不误报"任务已完成"；
> 2. 进行中的每一步都是用户能看懂的话（"正在查找相关内容…"而不是工具名）；
> 3. 审批、失败、并发都要**可见且可操作**，不静默丢任务；
> 4. 技术信息只出现在"查看技术详情"折叠区。

---

## 0. 环境准备（一次即可）

| 步骤 | 操作 |
|---|---|
| 0.1 | 启动基础设施：`docker compose up -d`（Postgres/MySQL/Redis/Qdrant/Java backend） |
| 0.2 | 启动 Java Backend（8080）与 Creator（8092），确认 `/health` 正常 |
| 0.3 | 启动 Agent API：`uv run uvicorn greenbook_agent_api.main:app --port 8094` |
| 0.4 | 启动前端：`.\scripts\start-fe.ps1`（若报 `Unknown command: "pm"`，说明 npm.ps1 shim 问题，已修复为走 npm.cmd） |
| 0.5 | 浏览器打开 http://127.0.0.1:5173 并登录 |

每个用例独立可跑；做完一个在结果栏打勾。

---

## A. 面板基础

### A1 打开面板，恢复会话与历史

- **操作**：首页右下角打开 Agent 面板。
- **预期**：
  - 能进入之前的会话（有标题），历史消息正常显示；
  - 若上一轮有没做完的任务，打开后能看到它还在"正在做什么"（不丢）；
  - "Agent记忆"折叠区显示"当前为只读"，勾选框禁用，没有删除/清空按钮。
- **验证点**：面板重开不丢状态；记忆只读（阶段二改动）。

### A2 新用户自动建会话

- **操作**：清空浏览器后打开面板，输入一句话发送。
- **预期**：自动创建新会话并开始处理，无需手动建会话。

---

## B. 检索与总结（只读路径）

### B1 检索 + 总结

- **操作**：输入 `帮我找几篇关于 Agent 的帖子并总结共同方法` 发送。
- **预期**（按时间顺序）：
  1. 发送后**立刻**看到自己的消息上屏，并出现"正在查找相关内容…"之类的**真实业务动作**（不是"任务已提交"）；
  2. 进行中卡片逐步更新（"已查找相关内容"→"已阅读代表性内容"→"正在整理共同观点…"）；
  3. 完成前**任何时刻都不出现"已完成/成功"字样**；
  4. 完成后看到结果卡片："找到 N 篇相关内容"+ 来源帖子列表 + 共同观点总结；
  5. 整个界面**不出现** `execution_id`、`task_id`、工具名（`community.search_public_posts` 之类）或英文技术词；技术详情要展开"查看技术详情"才有。
- **验证点**：不误报完成；进度用户语言；技术信息隔离（0813）。

### B2 空结果 / 失败

- **操作**：输入一个几乎不可能有结果的查询（如 `帮我找关于 XX 量子咖啡机的内容`）。
- **预期**：不崩溃；结果卡片提示"没有找到足够相关的内容"，并允许继续输入；失败原因用户能看懂，不含堆栈。
- **验证点**：失败可见、可继续（不能静默丢）。

---

## C. 创作与发布（写路径 + 审批）

### C1 生成草稿

- **操作**：先做 B1，然后输入 `把上面找到的内容写成一篇帖子` 发送。
- **预期**：
  1. 立即出现"正在生成内容…"；
  2. 完成后出现草稿卡片：标题 + 摘要 + "查看草稿"跳转；
  3. 界面不出现 `GENERATE_CONTENT` 等 capability 名。
- **验证点**：写路径结果可见可跳转。

### C2 审批发布（确认路径）

- **操作**：输入 `生成一篇帖子并在周五 10:00 发布` 发送。
- **预期**：
  1. 先生成内容（进行中卡片）；
  2. 生成完成后**停在审批**：出现审批卡片"准备按计划发布"，展示发布时间（周五 10:00，本地时区）、内容预览，按钮为"确认发布 / 取消"；
  3. 审批未决时**不算完成**（没有完成卡片）；
  4. 点"确认发布"→ 任务继续 → 最终完成卡片：草稿已生成 + 已安排 `周五 10:00`；
  5. 此时若刷新/重开面板，任务状态仍是已完成且排期可见。
- **验证点**：审批流全链路（阶段一/二改动）；确认前不误报完成。

### C3 审批取消路径

- **操作**：同上，但在审批卡片点"取消"。
- **预期**：排期不生成；提示"已取消/发布安排没有成功"；草稿保留，可继续修改后重发。
- **验证点**：拒绝路径干净、可继续。

### C4 并发任务

- **操作**：连续发送两条独立请求，例如：
  - 消息 1：`再帮我查一下性能调优的帖子`
  - 消息 2：`另写一篇关于状态管理的草稿`
  两条**不等对方完成**。
- **预期**：两张任务卡片同时更新、互不阻塞；都完成后各自出结果；没有一条被另一条覆盖。
- **验证点**：独立任务并发、不因统一会话排队（0813 性能）。

## D. 会话与上下文

### D1 多轮引用

- **操作**：完成 B1 后输入 `把上面总结的方法整理成 5 条要点`（不重新描述背景）。
- **预期**：Agent 记得上一轮内容，正确整理，不需要你重复上下文。
- **验证点**：上下文连续性。

### D2 长会话（历史压缩）

- **操作**：在同一个会话连续发送 25 条以上消息（可混合 `继续`、`好的` 等短句）。
- **预期**：
  - 会话不卡顿、消息区仍正常滚动；
  - 早期消息被折叠为摘要后，继续问早期内容（如 `第一轮说的是什么`）Agent 仍能回答要点；
  - 页面不报错、不重复显示同一条摘要/同一条消息。
- **验证点**：历史裁剪 + 摘要去重（阶段三 #19）。

### D3 执行中重开面板

- **操作**：发一条会执行较久的请求（如生成+发布），在它运行时**关掉面板再打开**。
- **预期**：打开后任务卡片恢复，仍在"正在做什么"的正确阶段（不是丢成空白，也不是误报已完成）；完成后正常出结果。
- **验证点**：面板重开恢复活跃 Run（阶段二改动）。

## E. 可靠性与边界

### E1 依赖抖动（队列退避）

- **操作**：执行中途停掉 Java Backend（8080）约 10 秒再启动，期间让 Agent 执行需要它的任务（如发布/获取社区内容）。
- **预期**：任务**不会失败消失**；恢复后自动继续并完成；用户看到的是"等待依赖恢复"之类的用户语言提示，而不是红色错误堆栈。
- **验证点**：队列 transient 退避 + 重投（阶段三 #18）。

### E2 重复发送（幂等）

- **操作**：快速连点两次发送按钮（或网络慢时重复点）。
- **预期**：只创建一个任务；不出现两条重复的"正在生成"任务。
- **验证点**：Idempotency-Key 幂等（阶段一改动）。

### E3 重复审批 / 过期审批

- **操作**：审批卡片出现后，先在另一标签页刷新，再回来点"确认发布"；或审批停留超过 TTL。
- **预期**：不产生二次执行；界面给出可理解的提示（如"审批已失效，请重新发起"），不出现重复排期。
- **验证点**：审批原子 CAS + 过期处理（阶段二/三改动）。

### E4 网络错误提示

- **操作**：发送请求前停掉 Agent API（8094），发送一条消息。
- **预期**：界面给出"Agent 服务不可用"之类的明确错误，输入框可重试，不崩溃。
- **验证点**：错误对用户友好。

---

## F. 技术信息隔离（全局）

### F1 全程无技术字段泄漏

- **操作**：把 A–E 走一遍，随时检查界面。
- **预期**：主界面任何地方都不出现：`execution_id` / `task_id` / `run_id` / `GoalTree` / `Step` / `ToolCall` / `Checkpoint` / `Worker` / MCP 工具名 / capability 英文名；以上只允许出现在"查看技术详情"折叠区内。
- **验证点**：0813 用户体验优先总则。
